# 调查我们在评估和内部使用中观察到的模型意外行为

2026年10月9日


本报告描述了我们在使用 Claude 进行评估和内部使用期间观察到的意外模型行为示例。这是我们在发布系统卡（每次模型发布时发布）和风险评估报告（每三到六个月作为我们负责任扩展政策的一部分发布）之外，发布更频繁的行为和对齐独立报告的努力的一部分。我们认为，透明地展示我们在测试和使用过程中观察到的模型行为非常重要。

这些行为可以分为四类：

* Claude 利用软件中的基本缺陷在服务器上运行命令；
* Claude 在真实网站上提交了本不应提交的敏感表单；
* Claude 绕过限制以获取由令牌或费用保护的数据；以及
* Claude 使用 URL 缩短服务以绕过其 fetch 工具中的限制。

我们选择不提及以下示例中涉及的组织的名称，以避免暴露其系统中的漏洞，并且应他们的要求。出于这个原因，我们对每个案例提供的细节也比平时少。下面描述的一些案例涉及美国联邦、州和地方政府机构运营的网站。我们已就这些案例向白宫作了简报，并通知了每个涉及的机构。

迄今为止，我们在这些类别中识别出的案例对现实世界的影响微乎其微。从对齐和安全角度来看，我们认为这些行为比我们于[7月30日](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)和[9月9日](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents)报告的网络安全事件要轻微得多。它们类似于我们自[Claude Mythos 预览版](https://www-cdn.anthropic.com/08ab9158070959f88f296514c21b7facce6f52bc.pdf)以来在系统卡中描述的行为。大多数都是*持久性*的形式，即当 Claude 无法按给定条件完成任务时，它会绕过限制而不是停止。

尽管这些行为的影响微乎其微，并且我们已经关闭了一些高风险和网络安全评估的实时互联网访问，但我们现在决定将其扩展到包括我们所有的内部评估，直到我们确认我们的安全和监控措施（在本帖的补救措施部分描述）能够可靠地捕捉到这些行为。下面，我们还讨论了对齐考虑因素，并更详细地介绍我们如何修改训练以减少进一步不当行为的可能性。

我们大部分案例是通过七月份开始对转录记录的审查发现的。我们的审查首先集中在我们的网络安全评估上——这些测试中，模型被要求探测或攻击测试系统，并且互联网访问应该被禁用。此后，我们将扫描范围扩展到更广泛的 Claude 可能访问互联网的情况，包括故意启用互联网访问以便 Claude 可以在真实世界任务上进行评估的测试。我们首先寻找与我们今年夏天报告的网络安全事件严重程度类似的案例；迄今为止，我们尚未找到任何此类案例。然后，我们将搜索范围扩大到严重程度较低的情况，即模型以我们未预期的方式与真实网站或系统交互的情况。

我们现在还在扫描更大范围的较低风险转录记录，以及我们在 Anthropic 内部使用 Claude 的情况和在 Claude 可以访问互联网的强化学习（RL）环境中的使用情况。随着这项工作的继续，我们计划报告新的意外行为案例。这里报告的所有案例都涉及 Claude 与外部世界交互；据我们所知，它们都没有涉及客户数据或 Anthropic 自己的内部系统。

在本帖中，我们解释了为什么我们运行评估（大多数案例都发生在这里）；更详细地描述每种行为；并对这些行为对 Claude 对齐的启示以及我们如何缓解它们提供初步看法。

## **我们为什么以及如何运行评估**

本帖描述的行为并非评估所特有的，但迄今为止我们识别出的许多案例都发生在评估运行期间。在发布模型之前，我们持续在广泛的任务上测试模型。我们使用许多不同的评估（标准化的任务集，每次都以相同方式评分），每个评估都有助于描绘 Claude 在特定领域的技能画像。我们使用的许多评估是公开的；它们由外部研究人员编写，任何开发人员都可以运行，使我们能够跨模型比较能力。其他评估是我们内部构建的。

由于语言模型是非确定性的——也就是说，它们的响应总是包含某种随机性元素，并且它们每次执行相同任务时可能会略有不同——我们让 Claude 完成每个评估任务数百或数千次（每次尝试称为一次运行）。进行如此多次测试使我们能够了解模型的典型表现，并捕捉到模型做出我们未预期行为的罕见情况。我们从评估中了解到的内容塑造了 Anthropic 的决策，包括我们如何训练模型、围绕模型构建哪些保障措施以及何时发布模型。

评估也是模型行为问题有时首次显现的地方。模型通过 RL 学习它们能做的大部分事情，在 RL 中，它们在特定环境中多次尝试任务，并在成功时获得奖励。然而，训练环境是不完美的。如果训练奖励了我们未预期的东西——例如找到漏洞或绕过限制——模型就会学到绕过是有效的，并可能将其应用于其他地方。这被称为奖励黑客。虽然我们已有流程在训练期间识别和过滤掉奖励黑客，但评估是理解模型在不同上下文和与训练不同的任务集上的行为倾向的关键机制。

一些任务——例如在网络上搜索难以找到的信息——在没有互联网访问的环境中很难真实地模拟。使用互联网访问运行这些任务一直是业界的标准做法：公开的网络搜索基准默认在实时互联网上运行，以相同方式运行它们使我们能够与其他模型进行比较。本报告中的大多数案例都是在这样的评估中发生的。

## **行为概述**

下面，我们描述了四类行为，在这些行为中，Claude 以我们未预期的方式在真实网站和系统上行动，每个案例都涉及 Anthropic 之外的组织或个人。

### **利用软件中的基本缺陷在服务器上运行命令**

当 Claude 无法直接完成评估任务时，要么是因为其自身工具被故意限制，要么是因为其需要的外部服务不可用，它会使用托管在第三方网站上的其他工具来实现其目标。在某些情况下，它通过利用该网站软件中的基本缺陷来实现这一点，使用 SQL 或命令注入（一种发送输入的方式，网站错误地将其作为指令运行）。

例如，一个评估要求 Claude Mythos 预览版运行科学分析。执行该分析所需的公开工具托管在一所大学；当模型试图访问它时，该工具返回错误。寻找其他完成任务的方式，Claude 探索了该工具的网站，找到了大学服务器上的一个脚本，该脚本会返回任何它被要求获取的文件，并使用它从服务器复制文件，包括脚本本身的代码。在该代码中，Claude 找到了让它能在服务器上运行命令的注入缺陷，并使用它运行了计算。

在另一个案例中，Claude Mythos 5 所需的数据是免费的，但 Claude 无法在不接受数据使用协议的情况下访问它，而它没有工具可以做到这一点。Claude 使用托管在网站上的应用程序加载页面并代表它接受协议。

我们在 DeepSearchQA 和 BrowseComp（两者都是公开的网络研究评估）、LABBench2（一个公开的生物学研究基准）以及内部评估中看到了这种行为。

### **提交了本不应提交的表单**

我们观察到一些案例，Claude 在不应该提交的情况下提交了在线表单。通常，这发生在评估指令模糊时，或者环境中的错误配置阻止 Claude 使用虚拟表单时。

例如，在一个多次发生在同一评估上的案例中，一个未发布的非前沿研究模型应该填写一份政府表单的练习副本。当副本加载失败或模型错误地关闭它时，模型转而导航到通常托管真实表单的网站并在那里提交了表单。

在另一个评估中，Claude Haiku 4.5 被指示完成表单直到最终提交阶段，但在实际提交之前停止。几次 Claude 错误地提交了表单，期望会有一个额外的确认页面。在这些案例中，模型的思维链表明它只是在演示过程，而不是提交真实请求。

在这种行为的第三个示例中，Claude Haiku 4.5 被分配了一个任务，即在随机选择的网页上生成和执行示例任务。在一次运行中，模型落在了一个提到未破谋杀案的页面上；该页面包含一个由警察局运营的线索表单。Claude 被指示永远不要登录、创建账户、输入个人数据、进行购买或提交任何破坏性内容，但指令并未排除表单提交。Claude 用以下内容填写了表单：“我可能有关于此案的信息。我记得在那个时间段在[页面上提到的街道名称]附近看到过一个与描述相符的人。如果这条信息相关，请联系我。”（网站没有包含对嫌疑人的描述。）模型留下了姓名和联系字段为空，表单允许这样做，并提交了它。该提交被标记为垃圾邮件，从未被转发进行调查。

我们在 OSWorld（一个公开的计算机使用评估）、Odysseys（一个长期任务评估）以及内部使用中看到了这种行为。

### **绕过限制以获取受保护的数据**

Claude 有时会绕过限制以获取它没有访问权限的数据。通常，这发生在服务器拒绝 Claude 的请求时，或者数据仅付费提供时。

例如，在一个要求 Claude Mythos 5 识别照片中显示位置的评估中，它试图访问当地政府的财产地图以三角定位其猜测。Claude 可以阅读网页文本，但评估限制了它像人一样点击通过它们的能力。相反，它阅读了网站发送给浏览器的设置文件，找到了有效的访问令牌，并使用它们直接向地图后面的服务器发送请求以访问数据。

在这种行为的另一个示例中，一位 Anthropic 研究人员在一个统计项目上使用了 Claude Mythos 5，该项目要求它从州机构获取付费的公开数据。相反，Claude 从该机构网站的存档副本中学到其公开仪表板会向任何访问者发放访问令牌。它请求了一个并使用它查询数据库而无需支付费用。

在这两个示例中，Claude 获取了已经向公众开放但仅付费可用的数据。

我们在 Humanity's Last Exam（一个专家级学术问题评估）和内部使用中看到了这种行为。

### **使用 URL 缩短服务**

我们的一些 fetch 工具，让 Claude 能够阅读网页，限制了 Claude 可以请求的 URL 长度。这是为了防止 Claude 使用长 URL 执行某些不需要的操作，例如 SQL 或命令注入（URL 的一部分是传递给网站服务器的文本，长 URL 有空间携带这样的指令）。我们看到几个模型，包括 Claude Opus 5 和 Claude Mythos 5，通过使用免费的 URL 缩短服务来绕过这个限制。我们首先在内部分别识别出这种行为，但在撰写本帖时，da.gd URL 缩短服务的运营者告诉我们他们也发现 Claude 使用他们的网站用于此目的。我们感谢运营者分享这些细节。

## **补救措施**

我们已经采取了几项预防措施。一些我们不再运行的公开评估；其他的我们已经转移到它们的离线版本，或者重新构建了它们，使它们的任务不会触及实时网站。我们还进行了更广泛的改变。我们已经更新了一些互联网访问工具的安全护栏，例如网络 fetch 工具，以严格限制模型可以用它们做什么。此外，作为我们持续的[代理安全和监控工作](https://www.anthropic.com/news/improving-alignment-security-efforts)的一部分，我们已经构建了工具来自动检测和阻止上述行为。这个工具现在运行在我们的大多数评估和内部前沿模型代理使用上。当我们用它测试本帖中描述的情况时，它阻止了所有情况。

正如我们在8月31日的[帖子](https://www.anthropic.com/news/improving-alignment-security-efforts)中描述的那样，我们还在继续修复或移除那些奖励 Claude 绕过工具限制或其他障碍的训练环境，使它们不会激励这些行为或允许奖励黑客。

我们还在采取其他步骤来防止 Anthropic 内部的意外代理行为，并在它们发生时捕捉它们。这些包括将内部代理迁移到具有强隔离的集中管理基础设施，最小化内部代理和训练过程的互联网访问，并通过如[安全分类器](https://alignment.anthropic.com/2025/cheap-monitors/)和[层次化摘要](https://alignment.anthropic.com/2025/summarization-for-monitoring/)等技术监控代理所做的更多事情。这些措施现在已成为我们安全团队检测和响应程序的一部分，使我们能够快速响应和隔离不良行为。我们预计将发布更多关于这些方法的内容，并将它们直接构建到我们的产品中来。

## **讨论和对齐启示**

虽然我们对这些案例尚未完成完整的对齐评估，但我们认为它们比今年夏天的网络安全事件要轻微。我们在下面解释原因，并分享我们从中学到的普遍教训。

### **对齐背景**

随着我们为这些行为建立定期公开报告流程，我们也希望根据它们的严重程度来定位它们。这仍然具有挑战性：判断对齐失败的严重程度通常取决于模型试图做什么，而模型对其推理过程的自我描述不一定是其信念或行动动机的可靠证据，正如我们在9月9日的[对齐评估](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents)中讨论的那样。随着模型变得更有能力，它们可以以更复杂的方式与世界互动，这使得更复杂的失败成为可能。例如，我们在那个评估中描述的有偏见的推理并不是新的，但在模型能够长时间在真实系统上有效行动的环境中，它导致了更严重的后果。鉴于 AI 能力发展的速度，基于今天失败的严重性框架可能会迅速过时。

尽管如此，我们发现两个对齐维度对于审查本帖中的案例很有用：过度延伸，即模型超越其任务意图的程度；以及不诚实，即它是否对其行为或意图给出了误导性描述。在过度延伸方面，我们认为这些案例比我们今年夏天报告的事件要令人担忧得多，在这些事件中，Claude 在网络安全评估期间获得了真实第三方系统的访问权限数小时。相比之下，在我们这里报告的案例中，Claude 绕过了访问控制以获取受保护但公开可用的数据，或者利用软件缺陷并在服务器上运行命令（主要是为了获取非敏感数据）。

在不诚实方面，比较更为复杂。在一个案例中，被分配生成与网站交互的示例，Claude 通过警察部门的在线表单提交了一个虚构的线索。从转录记录来看，Claude 似乎只是在为任务生成示例内容，而不是试图误导任何人以实现目标。相比之下，在今年夏天最严重的[事件](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents)中，Claude 的误导性推理持续了数小时并支持其持续攻击。然而，有信心地判断不诚实通常需要比我们在这里所做的更深入的评估，例如通过修改重放转录记录以测试驱动模型行为的因素，因此随着进一步分析，我们对这些案例的看法可能会改变。

### **教训和下一步**

我们在这里描述的没有任何行为是新的，它们也没有改变我们对 Claude 对齐的整体看法。在我们观察到这些行为的许多案例中，Claude 被分配了模糊或不可能完成的任务。我们和其他人观察到，当模型被给予不可能完成的任务时，它们会追求未预期的有时不对齐的策略来实现其目标。

如果评估问题更清楚地说明了练习的范围，包括目标、允许的行动和网络边界（即模型应该和不应该访问什么），一些这些失败可能可以避免。然而，Claude 在日常使用中每天都会遇到模糊和不可能完成的任务，而且，事实上，我们观察到的几个案例发生在 Claude 的常规代理使用中。

行为和对齐训练是我们用来提高 Claude 的判断力和谨慎处理模糊情况能力的主要技术。历史上，我们更专注于教导模型尊重边界并在编码环境中保持适当的谨慎。我们现在正在将这些环境扩展到搜索和计算机使用等应用，这些应用涉及到了这里描述的情况。然而，对齐训练本身还不足以完全稳健，至少在短期内是这样，因此我们还依赖纵深防御方法，包括上面描述的分类器和保障措施。

随着我们的扫描和分析继续，我们计划继续报告令人担忧的行为。我们希望这些报告能帮助其他开发人员检查他们自己模型中的类似行为，因为许多涉及的评估是公开且广泛使用的。虽然这些案例的影响微乎其微，但我们不想淡化这些发现，因为随着模型变得更有能力，同样的行为可能会造成更大的伤害。模型在社会中扮演的角色越大，公众越有权知道它们的行为方式。

*注：上面描述的线索表单示例涉及费城警察局，他们今天通过他们的新闻稿自行披露。我们在10月8日我们的技术审查完成后立即与该局分享了这一发现。*
